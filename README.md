# E-Commerce MCP Server

Model Context Protocol (MCP) server providing AI clients with standardized, read-only access to product information in the e-commerce platform.

## Architecture

```text
MCP Client
    |
    | Model Context Protocol (stdio/SSE)
    v
FastMCP Server (ecommerce_mcp_server)
    |
    | REST (HTTP GET)
    v
Product Service (Microservice)
    |
    v
Product DB
```

## Authentication Architecture (Phase 2)

Phase 2 reuses the existing HMAC-signed access JWT generated by User Service (`POST /api/auth/login`). FastMCP authenticates the MCP request via its authentication context layer and propagates the existing access token downstream to the Product Service via standard `Authorization: Bearer <access-token>` headers. The MCP server does not generate tokens, store credentials, or duplicate authorization logic.

```text
User Service
    ↓
Access JWT
    ↓
MCP Client
    ↓
FastMCP authentication context
    ↓
ProductServiceClient
    ↓
Product Service
```

### Security & Token Flow
- **No Token in Tool Schemas**: Business tools (`get_product`, `search_products`) strictly exclude token arguments from their parameters.
- **Request-Scoped Context**: The token is resolved from FastMCP's authentication context (`get_access_token()`).
- **No Token Leakage**: Tokens, claims, and internal trace details are never logged or included in tool outputs or error messages.
- **Authoritative Validation**: Product Service performs Spring Security JWT validation and authorization checks; MCP acts strictly as an adapter.

## Tools (Phase 1 & Phase 2)

### 1. `search_products`
Search and filter products using the Product Service search endpoint (`GET /api/products/search`).

- **Parameters**:
  - `search` *(str, optional)*: Free-text search query across product name, brand, and description.
  - `categoryId` *(str, optional)*: Category UUID filter.
  - `minPrice` *(Decimal/number, optional)*: Minimum price filter (>= 0).
  - `maxPrice` *(Decimal/number, optional)*: Maximum price filter (>= 0, >= minPrice).
  - `brand` *(str, optional)*: Brand name filter.
  - `status` *(str, optional)*: Product status filter (e.g., `ACTIVE`).
  - `page` *(int, default=0)*: Page index (0-indexed).
  - `size` *(int, default=10)*: Page size (default 10, max 100).

### 2. `get_product`
Retrieve details of a specific product by its UUID (`GET /api/products/{id}`).

- **Parameters**:
  - `productId` *(str, required)*: Valid UUID of the product.

## Configuration

| Environment Variable | Description | Default |
|----------------------|-------------|---------|
| `PRODUCT_SERVICE_URL` | Base URL of the backend Product Service | `http://localhost:8082` |
| `AUTH_REQUIRED` | Enforce authenticated context on MCP tool invocations (`true`/`false`) | `false` |

## Running the Server

Using `uv` or Python:
```bash
# Run via module entrypoint
python main.py

# Or via installed console script
ecommerce-mcp-server
```

## Running Tests

Execute the automated test suite:
```bash
python -m unittest discover -s tests -p "test_*.py" -v
```
